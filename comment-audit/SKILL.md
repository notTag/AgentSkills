# Comment Audit

Validate that every comment in the target accurately describes the code it annotates. Read-only. No modifications.

## Step 0: Determine target scope

Parse the argument passed after `/comment-audit`:

- `--diff [base]` flag present → **diff mode** (see Step 0b); base defaults to `main`
- No argument → scope = repo root (`.`)
- Path to a file → scope = that single file
- Path to a directory → scope = all source files under that directory (recursive)

## Step 0b: Diff mode — extract affected comment–code pairs

Run: `git diff <base>...HEAD` (three-dot: tip of current branch vs. base, excludes base-only changes).

If that returns nothing (branch is at base), fall back to `git diff HEAD` (uncommitted changes).

From the unified diff output, build the **affected set** — the comment–code pairs to audit:

**Case 1 — Comment line is in the diff** (`+` or `-` prefixed): the comment itself changed.
- Collect the comment and the code immediately following it in the current file state.
- Always include in audit set regardless of direction (`+` added = new comment to validate; `-` removed = skip, nothing to audit).

**Case 2 — Code changed near an existing comment** (comment line NOT in diff, but changed `+`/`-` lines are within N lines of a comment in the current file):
- N = 8 lines (enough to catch "comment above function, body changed inside")
- Collect the comment and the full current code block it annotates.
- This is the primary staleness signal: code moved under a comment that wasn't updated.

For each affected file in the diff:
1. Read the current file state (not the diff) to get accurate line numbers and full context.
2. Parse the hunk headers (`@@ -a,b +c,d @@`) to know which line ranges changed.
3. Walk the file's comments; include any comment whose annotated code overlaps with a changed line range (±N lines).

**Diff mode summary line** (prepend to report):
```
Diff base: <base>  |  Files changed: N  |  Hunks: N  |  Comment–code pairs in scope: N
```

Skip Step 1 (full file collection) entirely when in diff mode — only process files that appear in the diff.

## Step 1: Collect source files

For a single file: use it directly.

For a directory or repo: find all source files. Skip:
- `node_modules/`, `vendor/`, `.git/`, `dist/`, `build/`, `__pycache__/`, `.venv/`
- Binary files, lock files (`*.lock`, `bun.lockb`, `package-lock.json`)
- Generated files (check for `// @generated`, `# generated by`, `DO NOT EDIT` markers at top)
- Test fixture files (`.fixture.`, `.snap`, `__fixtures__/`)

Supported extensions: `.ts`, `.tsx`, `.js`, `.jsx`, `.mjs`, `.cjs`, `.py`, `.go`, `.rs`, `.rb`, `.java`, `.kt`, `.swift`, `.c`, `.cpp`, `.h`, `.cs`, `.php`, `.sh`, `.bash`, `.zsh`

## Step 2: Extract comment–code pairs

For each file, extract every comment along with its surrounding code context. Comment styles by language:

| Style | Languages |
|-------|-----------|
| `// single line` | JS/TS, Go, Rust, Java, Kotlin, Swift, C/C++, C#, PHP |
| `/* block */` | JS/TS, Go, Rust, Java, Kotlin, Swift, C/C++, C#, PHP |
| `/** JSDoc/JavaDoc */` | JS/TS, Java, Kotlin, PHP |
| `# single line` | Python, Ruby, Shell, Bash |
| `"""docstring"""` / `'''docstring'''` | Python |
| `--` | SQL, Lua |

For each comment, capture:
- The comment text (stripped of delimiters)
- The **code it annotates**: the function/block/statement immediately following an inline comment, or the function/class/block the comment precedes if it's a block comment
- Line number range
- File path

**Ignore:**
- Commented-out code blocks (lines that are syntactically valid code, just commented — flag separately as DEAD_CODE)
- License headers at file top (copyright/SPDX blocks)
- TODO/FIXME/HACK/NOTE/XXX markers — audit separately in Step 3b
- Shebang lines (`#!/`)

## Step 3a: Classify each comment

Evaluate each comment against the code it annotates. Apply exactly one verdict:

**ACCURATE** — comment truthfully describes what the code does, why it exists, or a non-obvious invariant. No action needed.

**REDUNDANT** — comment only restates what the code already says clearly. The identifier names and logic make the comment obvious.
- Example: `// increment counter` above `counter++`
- Example: `# returns the user` above `return user`

**STALE** — comment references behavior, parameters, return values, variable names, or logic that no longer exists or has changed.
- Look for: named variables that don't exist in scope, described behavior contradicted by the actual logic, parameter names that don't match the function signature, described return types that don't match, references to functions/methods that have been renamed or removed.

**MISLEADING** — comment describes X but the code does Y — an active lie. Higher severity than STALE.
- Example: `// returns null if not found` but code throws an exception
- Example: `// idempotent` but code has side effects on every call
- Example: `// sorted ascending` but array is reversed

**ORPHANED** — comment refers to code that has been deleted or moved away. Comment is now floating with no relevant code nearby (within ~5 lines).

**DEAD_CODE** — the comment is actually commented-out code, not an explanatory comment.

## Step 3b: Classify TODO/FIXME markers

For each TODO/FIXME/HACK/XXX:
- Note the comment text
- Flag if it references an issue/ticket number (good practice — LINKED) vs. no reference (UNLINKED)
- Flag ANCIENT if the surrounding code hasn't changed in a long time (skip if no git blame available)

## Step 4: Process ALL pairs before reporting

**Critical:** Do not emit any findings until every comment–code pair in scope has been evaluated. Accumulate all verdicts in memory, then produce the report in one pass. Never short-circuit on the first MISLEADING or STALE hit.

In diff mode this means: walk every file in the diff, every hunk, every comment–code pair within ±8 lines of a changed hunk. Only after the full pass is complete, move to Step 5.

## Step 5: Produce the audit report

Output format:

```
# Comment Audit: <target path>  [--diff <base> | full]

<diff mode only>
Diff base: <base>  |  Files changed: N  |  Hunks: N  |  Comment–code pairs in scope: N
</diff mode only>

## Summary

| Verdict     | Count | % of audited |
|-------------|-------|--------------|
| Accurate    | N     | N%           |
| Stale       | N     | N%           |
| Misleading  | N     | N%           |
| Orphaned    | N     | N%           |
| Redundant   | N     | N%           |
| Dead code   | N     | N%           |

## Findings

| Severity   | File | Line | Comment (truncated to 60 chars) | Why                                      |
|------------|------|------|---------------------------------|------------------------------------------|
| MISLEADING | src/auth.ts | 42 | "returns null if not found" | throws AuthError instead of returning null |
| STALE      | src/user.ts | 18 | "accepts userId as string" | param renamed to `id`, now type number   |
| ...        | ...  | ...  | ...                             | ...                                      |

<If any MISLEADING or STALE findings exist, append a code block per finding with full context:>

### Detail: MISLEADING — src/auth.ts:42
Comment: "returns null if not found"
Code:
  function findUser(id: string) {
    const user = db.find(id)
    if (!user) throw new AuthError('not found')  // ← contradicts comment
    return user
  }
Why: Comment says returns null but code throws AuthError on missing user.

<repeat Detail block for each MISLEADING and STALE finding only>

## Skipped
- Generated files: <list if any>
- License headers: <count>
```

**Ordering rules:**
- Summary table always shown
- Findings table: sort by severity (MISLEADING → STALE → ORPHANED → REDUNDANT → DEAD_CODE), then file, then line
- Detail blocks: MISLEADING and STALE only — these are the actionable ones
- Omit Findings table and Detail blocks entirely if zero non-ACCURATE findings

## Step 6: Exit behavior

After printing the full report:
- If any MISLEADING or STALE findings exist → exit with code 1 (pipeline fails)
- Otherwise → exit with code 0 (pipeline passes)

Print the final line before exiting:
- Fail: `RESULT: FAIL — N blocking finding(s) (MISLEADING: N, STALE: N)`
- Pass: `RESULT: PASS — all comments in diff are accurate`

This line is machine-parseable for CI log scraping independent of the table output.
